# План MVP архивации: vault-2025 → vault-2025-archive (v2)

## Тезис

Архивированные задачи и встречи 2025 года переносятся из vault-2025 в отдельный vault-2025-archive. Переносятся **только** ассеты, на которые нет ни одной ссылки из активных (неархивированных) ассетов. Это гарантирует zero dead links в активном vault.

## Фундаментальное правило

> **Ассет переносится в архив ТОЛЬКО если на него нет входящих ссылок из неархивированных ассетов.**

Если архивированная задача упоминается в активном проекте — она остаётся в vault-2025.

## Scope

### Критерии переноса (все одновременно)
- `archived: true`
- `exo__Instance_class` содержит `ems__Task` или `ems__Meeting`
- `ems__Effort_resolutionTimestamp` или `ems__Effort_endTimestamp` в 2025 году
- **НЕТ** входящих wikilinks (`[[uuid...]]`) из неархивированных ассетов
- Property `archived: true` сохраняется при переносе

### Что остаётся в vault-2025
- Прототипы (неархивированные `ems__TaskPrototype`, `ems__MeetingPrototype`)
- Классы и онтологии (неархивированные)
- Все остальные типы ассетов
- Архивированные задачи/встречи, на которые ссылаются активные ассеты

## Фазы

### Фаза 0: Инфраструктура (10 мин)
1. Создать `/Users/kitelev/vault-2025-archive/`
2. `git init`, `.gitignore`, `.obsidian/` (минимальная конфигурация для Obsidian)
3. Создать приватный GitHub repo `kitelev/vault-2025-archive`
4. Push initial commit

### Фаза 1: Онтологии (10 мин)
1. Собрать уникальные `exo__Asset_isDefinedBy` из кандидатов на перенос
2. Для каждой создать `!<name>_archive.md` (exo__Ontology, URL с /archive)
3. Положить в vault-2025-archive

### Фаза 2: Dry-run отчёт (15 мин)
1. grep: найти все кандидаты (archived + Task/Meeting + 2025)
2. Для каждого кандидата: grep по UUID во всех неархивированных файлах
3. Разделить на: "можно перенести" и "blocked (есть ссылки из активных)"
4. Отчёт:
   - Всего кандидатов: N
   - Переносится: M
   - Blocked: K (с указанием кто ссылается)
   - Уникальные isDefinedBy
   - Ожидаемое снижение триплов
5. **Ожидание подтверждения пользователя**

### Фаза 3: Git snapshot (2 мин)
```
cd vault-2025 && git add -A && git commit -m "pre-archive snapshot"
```

### Фаза 4: Инкрементальный перенос
**4а: Тестовая партия (10 ассетов)**
1. Обновить `exo__Asset_isDefinedBy` → archive ontology
2. Скопировать в vault-2025-archive
3. Удалить из vault-2025
4. Проверить: SPARQL vault-2025 работает, нет broken links
5. **Подтверждение от пользователя**

**4б: Основная партия (остальные)**
1. То же самое для всех оставшихся ассетов

### Фаза 5: Верификация (10 мин)
1. Подсчёт ассетов в vault-2025-archive
2. grep: нет UUID архивных ассетов в vault-2025
3. SPARQL: vault-2025 загружается, подсчёт триплов
4. Метрики до/после (файлы, триплы, время загрузки)
5. Commit + push vault-2025-archive
6. Commit vault-2025
